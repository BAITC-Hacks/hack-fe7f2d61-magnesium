# Backend handoff · SkillArena

Рабочая ветка: `frontend`. Главная точка входа: `app/page.tsx`. Frontend находится в корне Next.js-проекта. Backend-файлы и `app/api/` не создавались.

## Важное изменение требований

Пользователь подтвердил переход на официальный кейс: **бизнес-бриф → вопросы → подтверждённая карточка → рейтинг → каталог → предложение → ручной выбор бизнеса → подтверждённый этап**. Первоначальные Mission / Proof Mode не входят в этот MVP.

## AI endpoint, который frontend уже умеет вызывать

URL берётся из `NEXT_PUBLIC_BRIEF_API_URL`. Без переменной работает явно помеченный локальный demo adapter. Все детали вызова изолированы в `lib/brief-api.ts`; компоненты не знают провайдера модели.

```http
POST /api/brief/analyze
Content-Type: application/json
```

```json
{
  "brief": "Пользователи уходят из нашего приложения. Хотим повысить удержание.",
  "fields": {
    "context": "",
    "need": "",
    "data": "",
    "outcome": "",
    "criteria": "",
    "constraints": "",
    "users": "",
    "contact": "",
    "interaction": ""
  }
}
```

Успешный ответ — JSON object, не markdown и не строка с JSON:

```json
{
  "questions": [
    {
      "field": "data",
      "question": "Есть ли обезличенные данные об удержании или воронке онбординга?"
    },
    {
      "field": "criteria",
      "question": "По какой метрике и за какой период вы оцените результат команды?"
    },
    {
      "field": "constraints",
      "question": "Какие сроки, технологии и ограничения нужно учесть?"
    }
  ]
}
```

Ограничения: 3–9 вопросов; `field` только из девяти полей; без повторения одного поля; `question` — строка длиной 8–600 символов. Произвольные HTML-инструкции не исполняются. AI ничего не публикует и не выбирает команду.

Промпт, передаваемый в backend разработчику, экспортирован как `analysisPrompt`. Его текущая версия:

> Ты помогаешь бизнесу уточнить практическую задачу для студентов. Вход: {brief, fields}. Определи недостающие сведения и верни JSON {"questions":[{"field":"data","question":"..."}]}. Нужно от 3 до 9 разных уместных вопросов. Допустимые field: context, need, data, outcome, criteria, constraints, users, contact, interaction. Не добавляй факты и не заполняй поля за пользователя. Не выбирай команду. Не используй чувствительные признаки участников. Если всё заполнено, спроси о проверке критериев, данных и ограничений.

Backend должен хранить секрет провайдера, вызывать модель и проверять результат перед отдачей. Передавать frontend секреты через `NEXT_PUBLIC_` нельзя. Для разных origin нужен CORS на `http://127.0.0.1:3000` (и отдельно `http://localhost:3000`, если он используется).

## Обработка ошибок

- HTTP не 2xx → понятная ошибка, кнопки повтора и явного demo fallback.
- Некорректный JSON, меньше трёх вопросов, неизвестное поле, повтор вопроса → ответ отклоняется.
- Лимит ожидания — 15 секунд; уход с конструктора отменяет запрос.
- Не переключаемся на mock скрытно. Возвращаемый `source` у адаптера — `api` или `demo`.
- Demo не генерирует ответы. Заполнение фикстурами происходит только по отдельному нажатию пользователя и доступно для выбранного retention-примера.

## Остальные данные

Канонические frontend-типы: `BusinessTask`, `Proposal`, `Team`, `Workspace` в `lib/domain.ts`. Сейчас они сохраняются в `localStorage` под ключом `skillarena.workspace.v1` после runtime-проверки формы данных. Это ограничение frontend-демо, не серверное хранение.

Для подключения общего хранилища заменить чтение/запись и обработчики в `components/arena.tsx`; UI компонентов уже принимает данные и callbacks. Возможный REST-контракт ниже — **предложение для согласования, эти endpoints сейчас не реализованы и не вызываются**:

| Метод | URL                            | Действие                                             |
| ----- | ------------------------------ | ---------------------------------------------------- |
| GET   | `/api/tasks`                   | Общий каталог без фильтра по минимальному рейтингу   |
| POST  | `/api/tasks`                   | Сохранение черновика                                 |
| PATCH | `/api/tasks/:id`               | Изменение полей, сброс соответствующих подтверждений |
| POST  | `/api/tasks/:id/publish`       | Ручное подтверждение и публикация                    |
| POST  | `/api/tasks/:id/proposals`     | Новый отклик без ограничения количества              |
| PATCH | `/api/proposals/:id`           | Ручной статус `selected` / `rejected`                |
| POST  | `/api/proposals/:id/milestone` | Однократное начисление XP после принятия этапа       |

Если endpoint сохранения добавляется, backend должен проверять права, рейтинг и переходы независимо от frontend. Переключение роли в демо не является авторизацией.

## Что не менять при интеграции

- Не блокировать отклики на карточки с рейтингом ниже 40.
- Не назначать команду автоматически и не ограничивать выбор единственной командой.
- Не начислять XP за отправку предложения или выбор команды.
- Не выдавать AI-догадки за подтверждённые факты.
- Сохранять отдельное ручное подтверждение перед публикацией/обновлением.
- Не переписывать компоненты под provider-specific формат: преобразовать ответ внутри адаптера.
