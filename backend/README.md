# SkillArena backend

TypeScript + Fastify + SQLite, Node.js **24+**. Сервис работает отдельно от Next.js на порту 3001. SQLite сохраняет данные между перезапусками; внешняя БД не нужна.

## Быстрый запуск

```bash
cd backend
npm ci
cp .env.example .env
```

Впишите `OPENAI_API_KEY` в `.env` локально, затем:

```bash
npm run dev
```

- Swagger UI: http://127.0.0.1:3001/docs/
- OpenAPI JSON: http://127.0.0.1:3001/docs/json
- Health: http://127.0.0.1:3001/api/health
- Каталог: http://127.0.0.1:3001/api/tasks

Без ключа весь сценарий доступен через детерминированный fallback, явно обозначенный в каждом AI-ответе. При изменении `.env` перезапустите сервер. Для собранного приложения: `npm run build && npm start`.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `OPENAI_API_KEY` | пусто | Серверный ключ; не передавать в Next.js client bundle |
| `OPENAI_MODEL` | `gpt-4o-mini` | Модель с поддержкой Responses API и structured outputs |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | Провайдер, совместимый с **Responses API**, не только Chat Completions |
| `AI_TIMEOUT_MS` | `12000` | Таймаут запроса, включая чтение ответа |
| `PORT` / `HOST` | `3001` / `127.0.0.1` | Адрес сервера |
| `DATABASE_PATH` | `./data/skillarena.sqlite` | Файл SQLite; путь относительно рабочего каталога |
| `SEED_DEMO` | `true` | Однократное заполнение синтетическими примерами |
| `CORS_ORIGINS` | localhost/127.0.0.1:3000, :5173 | Разрешённые адреса фронтенда через запятую |

Для локальной сети настройте `HOST=0.0.0.0` и добавьте точный origin фронтенда в `CORS_ORIGINS`. Для хостинга нужен постоянный диск и один экземпляр сервиса. Этот SQLite-вариант не предназначен для эфемерных serverless-функций.

## Архитектура

```text
Next.js → REST /api → Fastify JSON Schema validation
                       ├─ Service → versioned drafts + published snapshots → SQLite
                       ├─ deterministic readiness scoring
                       └─ AI adapter → OpenAI Responses / strict JSON → quote validation / fallback
```

- `src/contracts.ts`: схемы запросов/ответов и типы.
- `src/service.ts`, `src/store.ts`: правила сценария и сохранение.
- `src/rating.ts`: прозрачная формула рейтинга.
- `src/ai.ts`: промпт, схема AI-ответа, проверка источников и fallback.
- `src/app.ts`: маршруты, ошибки, CORS, Swagger.
- `src/client.ts`: клиент для Next.js/браузера; серверные типы импортируются только как типы.
- `src/seed.ts`: пять черновиков, пять карточек, пять команд, пять откликов.

Полноценная регистрация не входит в MVP. `X-Business-Id: business-demo` и `X-Team-Id` — **переключатели демо-персонажей, не аутентификация**. Нельзя использовать этот MVP для закрытых данных или считать заголовки защитой аккаунтов. Все встроенные данные синтетические, адреса `example.test` и ссылки на прототипы — примеры.

## Рейтинг задачи

Рейтинг отражает заполненность **подтверждённых** сведений, а не известность компании, качество студента или автоматическую оценку истинности текста.

| Группа | Поля | Баллы |
|---|---|---:|
| Контекст и потребность | `context` 10 + `need` 10 | 20 |
| Данные | `data` | 20 |
| Ожидаемый результат | `expectedResult` | 15 |
| Критерии успеха | `successCriteria` | 15 |
| Ограничения | `constraints` | 10 |
| Пользователи | `users` | 10 |
| Связь с бизнесом | `contact` 5 + `collaborationFormat` 5 | 10 |

Непустое поле после trim приносит свой вес при подтверждении карточки. Пустые поля не начисляют баллы. Название обязательно для публикации, но не приносит баллов.

- `rating.score`: фактический подтверждённый рейтинг.
- `rating.previewScore`: сколько карточка получит после подтверждения.
- `rating.breakdown`: начисленные/возможные баллы по каждой группе.
- `rating.missingFields`: какие поля заполнить.
- `rating.unconfirmedFields`: заполненные поля, ожидающие подтверждения.

Уровни: `draft` 0–39, `working` 40–69, `ready` 70–89, `priority` 90–100. В каталоге видны **все опубликованные** задачи, включая 0–39. Низкий рейтинг не запрещает отклик. Неопубликованные черновики доступны в кабинете бизнеса.

Каждая правка увеличивает `version` и снимает подтверждение. После правки нужны `confirm`, затем `publish`. Пока этого не произошло, каталог показывает предыдущую подтверждённую публикацию. `409 CONFLICT` означает, что фронтенду нужно загрузить свежую версию. После ответа AI текущая версия проверяется повторно. Ручные изменения, в том числе намеренно пустые поля, сохраняются при последующей AI-генерации.

## API и демо

Полный контракт: [openapi.json](openapi.json). Примеры для Next.js: [frontend-integration.md](../docs/frontend-integration.md).

| Метод и путь | Действие |
|---|---|
| `GET /api/businesses`, `GET /api/teams` | Демо-персонажи и XP команд |
| `POST /api/teams` | Создать профиль команды |
| `POST /api/tasks` | Создать черновик из свободного текста |
| `GET /api/business/tasks`, `GET /api/business/tasks/:id` | Черновики и версии бизнеса |
| `POST /api/tasks/:id/clarify` | Минимум три уточняющих вопроса; не изменяет задачу |
| `POST /api/tasks/:id/generate-card` | Сохранить новую редактируемую версию по ответам |
| `PATCH /api/tasks/:id` | Ручная правка карточки |
| `POST /api/tasks/:id/confirm` | Подтвердить текущую версию |
| `POST /api/tasks/:id/publish` | Опубликовать подтверждённую версию |
| `GET /api/tasks?topic=Analytics&readiness=working` | Каталог, рейтинг по убыванию; также есть фильтр `industry` |
| `GET /api/tasks/:id` | Опубликованная карточка |
| `POST /api/tasks/:id/proposals` | Отклик команды без ограничения количества |
| `GET /api/tasks/:id/proposals` | Бизнес сравнивает отклики |
| `GET /api/team/proposals` | Отклики выбранной команды |
| `PATCH /api/proposals/:id/decision` | Бизнес выбирает (`selected`) или отклоняет (`rejected`) |
| `POST /api/proposals/:id/progress` | Бизнес подтверждает фактический этап; +100 XP |

Несколько откликов могут быть выбраны одновременно. Система не выбирает команды автоматически. У каждой команды стартовые 0 XP. Публикация и выбор команды XP не дают. Повтор одного `key` этапа с теми же данными возвращает прежний результат, с другими данными — 409. Отклонить отклик с уже подтверждённым прогрессом нельзя.

## AI: вход, выход и сбои

Используется [OpenAI structured output](https://developers.openai.com/api/docs/guides/structured-outputs) с `store: false`. Вход — исходное описание, текущая карточка, сведения о ручных правках и ответы на уточнения. Полный промпт и JSON Schema доступны в `src/ai.ts` (`SYSTEM_PROMPT`, `AI_OUTPUT_SCHEMA`).

Пример содержимого ответа модели:

```json
{
  "questions": [
    {"field":"users","question":"Для кого нужно решение?"},
    {"field":"successCriteria","question":"Как измерите успех?"},
    {"field":"constraints","question":"Какие есть сроки и ограничения?"}
  ],
  "extractedFields": [{"field":"data","quote":"Есть CSV заказов."}]
}
```

Каждая цитата должна дословно встречаться во входных данных. AI не может подставить выдуманный контакт, срок или бюджет. Сервер сохраняет человеческие ответы напрямую; неизвестные поля остаются пустыми. Итог всё равно требует ручного подтверждения. Самая первая часть исходного описания (до 4000 символов) используется как начальный контекст, полное описание сохраняется отдельно (до 12000).

`ai.mode` равен `live` только при успешном валидном ответе провайдера. Иначе `fallback` и `ai.reason`, например `missing_api_key`, `timeout`, `provider_http_429`, `invalid_schema`, `unsupported_facts`, `refusal`. Fallback возвращает вопросы по недостающим полям и собирает карточку из введённых ответов; не выдаёт себя за вызов AI. В интерфейсе показывайте состояние AI. Ключи и полный ответ провайдера не выводятся в ошибки клиента.

## Проверки и пятиминутная демонстрация

```bash
npm run check
npm test
npm run build
npm run export:openapi
```

Тесты используют настоящие Fastify и SQLite; внешний AI проверяется через локальный HTTP-сервер с валидными и ошибочными ответами. Покрыты рейтинг и его границы, публикация, сохранение после перезапуска, версия/конкурирующие правки, ручной выбор, XP, AI-таймауты, выдуманные цитаты, сохранение ручных правок и структура API.

После `npm run build` запустите `npm start` в одном терминале и в другом:

```bash
npm run demo
# Требовать настоящий AI; завершиться ошибкой при fallback:
npm run demo -- --require-live
```

`API_URL=http://127.0.0.1:3001` меняет адрес. Скрипт создаёт новые синтетические записи, проходит весь официальный сценарий, проверяет статус отклика и повторное подтверждение этапа. С ключом выполняет два реальных AI-запроса.

На защите покажите тот же сценарий в UI: слабый черновик → вопросы → ответы → рост preview → подтверждение рейтинга → публикация → отклик от студента → ручной выбор от бизнеса → подтверждение результата. Не показывайте только слайды.

## Контейнер

```bash
docker build -t skillarena-backend .
docker run --rm -p 3001:3001 --env-file .env -e HOST=0.0.0.0 -e DATABASE_PATH=/app/data/skillarena.sqlite -v skillarena-data:/app/data skillarena-backend
```

Dockerfile предоставлен как вариант запуска. Основные проверки проекта выполняются на Node.js 24; контейнер необходимо отдельно проверить в среде развёртывания.
